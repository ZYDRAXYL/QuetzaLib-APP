# 07 — Grill-me: คำถามที่เจ้าของต้องตัดสิน (QuetzaLib PC + Eco)

14 ข้อ · จัดเป็นรอบ: รอบ 1 ตอบได้ทันที · รอบถัดไปขึ้นกับคำตอบก่อนหน้า · ➡️ = คำตอบที่แนะนำ
คำถามระดับ Eco ทั้งหมด (repo สัญญา, `.zeco`, token, สิทธิ์ Z.I.Z) อยู่ที่ `ECO-CONTRACT.md` §16 (และ `GRILL-ME.md` ระดับ Eco เมื่อเขียนเสร็จ) — ไม่ถามซ้ำที่นี่

---

## รอบ 1 — ไม่มีคำถามอื่นต้องตอบก่อน

❓ **Q1** - **QuetzaLib PC สร้างด้วยอะไร**: แผนเดิมใน `chain.json` คือ QuetzaLib-EXE = Electron ห่อ `flutter build web`
แต่ทางนั้น DB อยู่ใน IndexedDB ของ Chromium (ไม่เป็นไฟล์ — MCP/locator/สำรองข้อมูลต้องมีสะพาน) ·
(ก) **Flutter Windows desktop จาก `lib/` เดิม** — DB/รูปเป็นไฟล์, ใช้โค้ด `_io` ที่มีแล้ว, ~25–40 MB, ตรงกฎ "source tree เดียว"; เสียกล้องใน Chromium และตาราง/แผงต้องเขียนเองใน Flutter ·
(ข) Electron ตามแผนเดิม — ได้ installer pipeline แบบ DraconDex-EXE และกล้องใน Chromium; DB มองไม่เห็น, 100 MB+, repo ที่สอง ·
(ค) Electron + สะพาน Node `better-sqlite3` — ได้ไฟล์จริงแต่ต้องเขียนชั้น DB ใหม่ทั้งชั้นสำหรับ desktop

➡️ (ก) — เป็นทางเดียวที่ DB เป็นไฟล์ที่แอปถือเอง ซึ่ง MCP ของ Eco ต้องใช้ และไม่ต้องดูแลโค้ดสองชุด

---

❓ **Q2** - **PC ทำอะไรได้บ้างเมื่อเทียบกับมือถือ**: (ก) **เท่ามือถือทุกอย่าง + งานจอใหญ่** (แก้หลายเล่ม, สแกนเนอร์ USB, Eco) — คนที่ไม่มีมือถือ Android ก็ใช้ได้ ·
(ข) PC = "โต๊ะทำงาน" สำหรับแก้/จัด/เชื่อม Z.I.Z, การเพิ่มหนังสือหลักอยู่บนมือถือ — ออกแบบหน้าจอน้อยลง แต่ Eco v1 เป็น PC-only ทำให้คนไม่มี Android เพิ่มหนังสือลำบาก ·
(ค) PC อ่านอย่างเดียว + ส่งให้ Z.I.Z

➡️ (ก) — ได้มาเกือบฟรีจาก `lib/` เดียว และ Eco v1 มีแต่ PC จึงต้องยืนได้ด้วยตัวเอง

---

❓ **Q3** - **ย้ายข้อมูลมือถือ ↔ PC ยังไง**: วันนี้มีแค่ `.zip` สำรองที่ "แทนที่ทั้งคลัง" (ไม่มี id กลาง รวมกันไม่ได้) ·
(ก) **`.zeco` (`qzl.library`) นำเข้าแบบรวมตาม `eid`** (ต้องเพิ่ม `eid` ทุกตาราง = DB v9 ทั้งมือถือและ PC) · การลบไม่ตามไป · ส่งไฟล์เอง ·
(ข) คง `.zip` แทนที่ทั้งคลังอย่างเดียว — ศูนย์งานแต่แก้สองเครื่องพร้อมกันไม่ได้ ·
(ค) โฟลเดอร์ sync (OneDrive/Drive) ไฟล์ต่ออุปกรณ์ + tombstone — อัตโนมัติ แต่ต้องเพิ่ม `deletedAt` ทุกตาราง + โค้ด merge มากขึ้น ·
(ง) sync ผ่าน LAN — แพงสุด
ข้อย่อย: ให้ปุ่ม "สำรองข้อมูล" ส่งออกเป็น `.zeco` แทน `.zip` ไปเลย (`.zip` เดิมยังนำเข้าได้) ใช่ไหม

➡️ (ก) ใน MVP + เปลี่ยนสำรองข้อมูลเป็น `.zeco` · (ค) เป็น later — ได้การรวมที่ถูกต้องก่อน แล้วค่อยทำให้อัตโนมัติ

---

❓ **Q4** - **คลังบน PC เก็บที่ไหน**: (ก) **`%LOCALAPPDATA%\QuetzaLib\library\`** (ซ่อน แต่มีปุ่ม "เปิดโฟลเดอร์คลัง") — ปลอดภัยต่อ SQLite ·
(ข) `Documents\QuetzaLib\` (แบบ Calibre มองเห็นง่าย) — เสี่ยงโดน OneDrive sync ไฟล์ DB ระหว่างเปิดอยู่ ·
(ค) ให้ผู้ใช้เลือกตอนเปิดครั้งแรก — ยืดหยุ่นแต่ต้องทำ "ย้ายคลัง" (path รูปเป็น absolute) ตั้งแต่ MVP

➡️ (ก) — ไม่มีความเสี่ยงข้อมูลเสียจาก sync และ Z.I.Z เข้าถึงผ่าน MCP อยู่แล้วโดยไม่ต้องเห็นไฟล์

---

❓ **Q5** - **คลังหนังสือเป็นส่วนหนึ่งของ "โปรเจกต์ Eco" หรือไม่**: โปรเจกต์ Eco = โฟลเดอร์ที่รวมงานของหลายแอป (เช่นนิยาย "Moonfall": DraconDex + BahaMyth + RyuLong) ·
(ก) **คลังเดียวส่วนตัว ไม่อยู่ในโปรเจกต์ไหน** — แอปอื่นลิงก์มาหาหนังสือด้วย Eco reference ·
(ข) หลายคลัง — คลังต่อโปรเจกต์ (เช่นหนังสืออ้างอิงของนิยายเรื่องนี้) ต้องมีตัวสลับคลัง + locator หลายแถว ·
(ค) คลังหลัก + "ชั้นหนังสือ" (หมวด/ค้นหาที่บันทึก) ที่ผูกกับโปรเจกต์ Eco

➡️ (ก) ใน v1, (ค) ถ้าต้องการภายหลัง — คอลเลกชันหนังสือเป็นของคนไม่ใช่ของโปรเจกต์ และไม่ต้องเปลี่ยนโมเดล "คลังเดียว" ของแอป

---

❓ **Q6** - **ธีม Eco (token DraconDex 32 ธีม) ใช้กับแอป Android ด้วยไหม**: `lib/` เดียวกัน ·
(ก) **ทุกแพลตฟอร์ม** — โค้ดธีมชุดเดียว แต่หน้าตามือถือเปลี่ยน (ผู้ใช้เดิมเห็นต่าง) ·
(ข) Windows เท่านั้น — ต้องมีธีมสองระบบใน `lib/theme.dart` ตลอดไป ·
(ค) ทุกแพลตฟอร์มแต่มือถือตั้งค่าเริ่มต้นเป็นธีมใกล้ของเดิม

➡️ (ค) — โค้ดชุดเดียว และผู้ใช้มือถือไม่สะดุดตอนอัปเดต

---

❓ **Q7** - **เพิ่มหนังสือบน PC ด้วยอะไร**: `mobile_scanner` ไม่มีบน Windows ·
(ก) **สแกนเนอร์ USB แบบ keyboard-wedge + พิมพ์/วาง ISBN** ใน MVP · webcam = later ·
(ข) ทำ webcam ด้วยใน MVP (`camera_windows` + ตัวถอดบาร์โค้ด = dependency ใหม่ 2 ตัว, กล้องโน้ตบุ๊กโฟกัสใกล้ไม่ดี) ·
(ค) ไม่ทำสแกนบน PC — ใช้มือถือสแกนแล้วย้ายด้วย `.zeco`
ข้อย่อย: เจ้าของมีสแกนเนอร์รุ่นไหน (เพื่อตั้งค่าเกณฑ์ "พิมพ์รัว" และเขียนหน้า help ให้ตรง)

➡️ (ก) — สแกนเนอร์ USB ราคาถูกและเร็วกว่ากล้องมาก โค้ดแทบไม่มี (มันคือคีย์บอร์ด)

---

❓ **Q8** - **OCR "สแกนเติมข้อมูล" บน PC**: ML Kit ไม่มีบน Windows ·
(ก) **Cloud Vision เท่านั้น** (โค้ดมีแล้ว, ผู้ใช้ใส่ API key เอง, เกินโควตาฟรีต้องจ่ายเงินกับ Google) — ไม่มีคีย์ = ซ่อนปุ่ม ·
(ข) ไม่มี OCR บน PC เลย ·
(ค) ทำ Windows OCR (`Windows.Media.Ocr`, ฟรี ในเครื่อง) — ต้องเขียน native/FFI, ภาษาไทยขึ้นกับ language pack ของเครื่อง

➡️ (ก) ใน MVP, (ค) เป็น later — ได้ฟรีจากโค้ดที่มี และ PC ใช้ OCR น้อยกว่ามือถือ

---

❓ **Q9** - **Z.I.Z (และ AI ของผู้ใช้) อ่านอะไรจากคลังได้**: ข้อมูลที่ออกทาง MCP ไปถึงผู้ให้บริการโมเดลของ agent ·
(ก) metadata เท่านั้น (ชื่อ ผู้แต่ง ISBN ซีรีส์ สถานะ หมวด คะแนน) ·
(ข) **(ก) + บันทึกส่วนตัว (`notes`, บันทึกในไทม์ไลน์) เมื่อผู้ใช้เปิดสวิตช์ต่อคลัง** ·
(ค) ทุกอย่างรวมรูปปก/หน้าที่ถ่ายไว้
และ Z.I.Z ลบหนังสือได้ไหม (สัญญาบังคับให้มี `eco_delete` แต่ยืนยันทุกครั้ง)

➡️ (ข) + ลบได้แบบยืนยันทุกครั้ง — บันทึกส่วนตัวมีค่าต่อการสรุปแต่ต้องเป็นการเลือกของผู้ใช้ รูปไม่จำเป็นต่องานค้น/แก้

## รอบ 2 — ขึ้นกับรอบ 1

❓ **Q10** - **ชะตาของ repo QuetzaLib-EXE** (ขึ้นกับ Q1 = ก): (ก) **ถอดออกจาก chain** — ลบ repo entry + 3 edges, `desktop` chain = `APP > WEB`, ถอดจาก `MIRROR_SETS`, แก้ `CLAUDE.md`/`chain/README.md`/DEV scripts ·
(ข) เก็บเป็น repo แพ็กเกจ (รับ build จาก APP แล้วทำ installer) — มีสองขบวน tag (`v*` กับ `exe-v*`) ที่ต้องตรงกัน ·
(ค) เก็บชื่อไว้เฉย ๆ ไม่มีงาน — chain มี repo ผีที่ `chained-updated` จะพยายามส่ง PR ไปหา

➡️ (ก) — installer ทำใน job เดียวของ `release.yml` ได้ และ chain ที่สั้นลงคือ chain ที่พังยากลง

---

❓ **Q11** - **ปล่อย Windows build แบบไหน** (ขึ้นกับ Q1, Q10): tag: (ก) **`v*` ขบวนเดียว — APK + Windows zip + setup.exe อยู่ใน release เดียวกัน** ·
(ข) tag แยก `win-v*` — release ที่ไม่มี `.apk` จะกลายเป็น `releases/latest` แล้วตัวอัปเดตบน Android พัง ·
ตัวติดตั้ง: zip แบบ portable **ต้องมี** (Hub รันเวอร์ชันเก่าด้วยมัน — ECO-K7) + เลือกเพิ่ม (1) **Inno Setup ต่อผู้ใช้ ไม่ต้อง admin** (2) MSIX (ต้องเซ็นเสมอ, sandbox ของ MSIX ทำให้ path `%LOCALAPPDATA%` ถูก redirect) (3) zip อย่างเดียว

➡️ (ก) + zip + Inno Setup — ตัวอัปเดตมือถือไม่พัง และไม่ต้องจ่ายค่าใบรับรองก่อนปล่อยได้

---

❓ **Q12** - **สีประจำ QuetzaLib ใน Eco** (ขึ้นกับ Q6): ECO-T2 ให้ต่างได้แค่ accent · มรกต `#1B7A3C` ของเดิมผ่าน contrast บนธีมสว่าง (ขาวบนมรกต ≈ 5.4:1) แต่ธีมมืดต้องใช้เฉดสว่างขึ้น
และ "จุดสีประจำแอป" (ชิปแหล่งที่มาในแอปอื่น) ห้ามอยู่ย่านเขียวที่แปลว่า "สำเร็จ" ·
(ก) **accent มรกต (ปรับเฉดต่อธีมให้ generator ผ่าน) + จุดสีประจำแอปเป็นเขียวหยก-ฟ้า** ·
(ข) ใช้ accent ของ DraconDex เหมือนแอปอื่น — เสียเอกลักษณ์ ·
(ค) มรกตทั้ง accent และจุด — ชนกับสีสถานะ "สำเร็จ"

➡️ (ก) — คงเอกลักษณ์เควทซัลไว้โดยไม่ทำให้สีสถานะกำกวม

---

❓ **Q13** - **ขอบเขต "แก้ข้อมูลจำนวนมาก" ใน MVP** (ขึ้นกับ Q2): (ก) **แผงแก้หลายเล่ม + หา/แทนที่ข้อความธรรมดา + พรีวิว diff + เลิกทำ** · regex, โหมดแก้ตาราง (วางจาก Excel), CSV เป็น v1 ·
(ข) ทุกอย่างใน MVP — release แรกช้าลงมาก และโหมดตารางเป็นงาน UI ที่ใหญ่ที่สุดใน Flutter ·
(ค) แผงแก้หลายเล่มอย่างเดียว ไม่มีหา/แทนที่

➡️ (ก) — พรีวิว diff ตัวเดียวกันใช้กับข้อเสนอของ Z.I.Z ด้วย พิสูจน์มันก่อนแล้วค่อยเพิ่มเครื่องมือที่ทำลายข้อมูลได้มากกว่า

## รอบ 3 — ขึ้นกับรอบ 2

❓ **Q14** - **ซื้อใบรับรอง code signing ไหม** (ขึ้นกับ Q11): .exe ที่ไม่เซ็นโดน SmartScreen เตือน "unknown publisher" ตอนติดตั้ง/เปิดครั้งแรก ·
(ก) **ไม่เซ็นใน v1** + เขียนหน้า help "กด More info → Run anyway" + ให้ Hub เป็นทางติดตั้งหลัก (Hub ตรวจ sha256 จากแคตตาล็อกที่เซ็นแล้ว — ECO-K2) ·
(ข) ซื้อใบรับรอง (มีค่าใช้จ่ายรายปี) ใช้ร่วมทุกแอปใน Eco ·
(ค) ใช้บริการเซ็นแบบคลาวด์ของ Microsoft (ต้องผ่านการยืนยันตัวตน)
ข้อนี้ควรตัดสินครั้งเดียวทั้ง Eco — คำตอบที่นี่ใช้เป็นคำตอบของ QuetzaLib จนกว่าจะมีคำตัดสินระดับ Eco

➡️ (ก) สำหรับ v1, (ข)/(ค) เมื่อ Eco มีผู้ใช้นอกวงคนรู้จัก — ค่าใช้จ่ายเกิดครั้งเดียวสำหรับทุกแอป จึงควรตัดสินที่ระดับ Eco
